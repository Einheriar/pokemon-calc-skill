# pokemon-calc 机制细节参考

> 本文件为 SKILL.md 的按需参考，不自动加载。当需要 SP/EV 换算细节、optimize 双模式返回字段，或数据来源的完整说明时，先阅读本文件。

## 能力点数（SP）与努力值（EV）双视图

本 Skill 底层始终以**努力值（EV）**存储与计算，同时提供《宝可梦冠军》(Pokémon Champions) 的**能力点数（SP）**作为输入与展示视图。SP 按下列公式映射到 EV；实际能力值仍由引擎结合等级、个体值、性格和取整计算，不能将每个 SP 无条件等同于最终能力值增加 1。

| 系统 | 总点数 | 单项上限 | 步进 | 投资换算 |
|------|--------|----------|------|-------------------------------|
| 能力点数（SP） | 66 | 32 | 1 | 正数 SP 按 `EV = 8 × SP - 4` 转换，0 SP 为 0 EV |
| 努力值（EV） | 508 | 252 | 4 | 保留原始 EV；实际能力值以计算结果为准 |

**输入与展示换算公式**：

- SP → EV：`EV = 8 × SP - 4`（SP=0 时 EV=0）
- EV → SP：`SP = (EV + 4) // 8`

| SP | 等效 EV | 说明 |
|----|--------|-----------|
| 1 | 4 | 首个 SP |
| 13 | 100 | 换算示例 |
| 31 | 244 | 换算示例 |
| 32 | 252 | 单项上限 |

> 关键：**32 SP 对应 252 EV**。在 50 级、31 IV 的常规能力值公式中，性格修正前首个能力值增量需 4 EV，之后通常每 8 EV 增加 1；性格修正与取整会改变最终增量。EV 转为 SP 展示时会丢弃不影响该标准条件能力值的投资余数，原始 EV 仍保留；其他等级或 IV 条件下请直接使用所需 EV 配置计算。

**命令示例**：

```bash
# 用户以 SP 表述（推荐）：用 sps 字段，引擎自动转 252 EV
python scripts/query.py calc 喷火龙 喷射火焰 水箭龟 --att_ov '{"sps":{"sp_attack":32}}'

# 用户以传统 EV 表述：直接用 evs 字段
python scripts/query.py calc 喷火龙 喷射火焰 水箭龟 --att_ov '{"evs":{"sp_attack":252}}'

# optimize 默认 EV 模式；Champions SP 优化用 --mode sp
python scripts/query.py optimize 喷火龙 喷射火焰 水箭龟 --goal ko --target ohko
python scripts/query.py optimize 喷火龙 喷射火焰 水箭龟 --goal ko --target ohko --mode sp
```

**optimize 返回值字段说明**：

`optimize` 命令始终返回两套字段以兼容双模式：

```json
// EV 模式（--mode ev，默认）
{
  "success": true,
  "optimal_ev": 252,
  "remaining_evs": 256,
  "optimal_sp": 0,
  "remaining_sp": 0
}

// SP 模式（--mode sp）
{
  "success": true,
  "optimal_ev": 0,
  "remaining_evs": 0,
  "optimal_sp": 25,
  "remaining_sp": 41
}
```

未使用模式的字段固定为 0，避免解析歧义。`remaining_evs` / `remaining_sp` 是替换被优化属性后的整套配置剩余额度：新最优值与其他属性的原分配都会扣除；SP 模式下其他属性按 `SP=(EV+4)//8`（EV=0 时为 0）转换。若原始配置已经超过总额度，剩余值返回 0。

## 半血招式与多次使用限制

愤怒门牙／自然之怒／大灾难在 KO 预测中逐次按剩余 HP 重算，未免疫且目标存活时至少造成 1 点伤害。若回复与持续伤害并存，或回复树果会在持续伤害后触发而当前模型尚未区分顺序，返回明确限制。蛮干／搏命仅评估当前伤害，不承诺连续使用时的击倒次数。`optimize` 对这五种招式的 2HKO／3HKO 或两击存活目标返回 `success: false, unsupported: true`；单次目标仍可查询。

## 太晶属性与入场时点

非星晶太晶的当前属性用于属性相克、接地、场地效果、天气防御加成和回合末持续伤害；星晶保留原属性。原属性另用于太晶 STAB，不能直接覆盖。`field_override` 的隐形岩／撒菱默认表示在本回合太晶前入场时已结算的伤害，因此使用原属性与当时接地状态，不用之后的太晶属性反推入场伤害。

星晶的 `stellar_boosted_types` 是已消耗首次增幅的属性数组。原本系首次为 2 倍、之后 1.5 倍，非原本系首次约 1.2 倍、之后 1 倍；太乐巴戈斯星晶形态持续获得增幅。星晶太晶爆发命中后攻击／特攻各降一级，生效的唱反调改为各升一级，单纯改为各降两级，仍夹紧至 −6～+6。引擎用私有快照逐次结算，不改变调用方的宝可梦、招式或场地。

太晶计算返回的 `next_state.attacker`／`defender` 可合并回对应配置继续计算，其中包含 `boosts`、`stellar_boosted_types`、`tera_effects_applied` 和 `item`。必须同时把 `next_state.field_override` 合并回场地配置。HP 没有自动扣除，调用者须选定一次真实伤害后设置下一次 `current_hp`。连续攻击 KO 使用每个伤害分支自己的 HP、树果和太晶状态；多段／亲子爱或回复与持续伤害混合等未建模组合会明确提示无法可靠计算。

太晶状态、可触发树果、HP 相关威力及满血减伤相关的多次攻击优化，`guaranteed` 检查所有伤害分支，`likely` 检查目标概率至少 50%，并返回百分数形式的 `ko_probability`／`survival_probability`。其余静态场景保留平均伤害阈值。优化保持既有范围，不把钉子、回合末回复／伤害加入阈值；状态连续多段明确不支持。

`tera_effects_applied: false` 表示本次太晶触发事件待处理：双方的归零化境先清天气／场地，面影辉映按面具提升对应能力一级，随后才计算招式分类、种子和伤害；能力等级仍夹紧至 +6。已有强化或太晶后新环境的快照应传 `true`，以免重放事件。化学变化气体压制的事件也视为已处理。这个标记只描述快照，不模拟换人；再次入场触发面影辉映时由调用者重置标记。

星晶形态的晶光星群改为星晶属性并攻击全部对手，太晶时攻击高于特攻则用物理分类，单打不套扩散减伤。棘藤棒按面具形态变属性，觉醒之舞读取当前第一属性，星晶保持原属性。各派生结果均由 `move_info` 回显。

## 万能伞的计算边界

万能伞只影响部分晴天／雨天效果，不清除场上天气。普通火／水招式的天气伤害倍率由防守方是否携伞决定，攻击方单独携伞不取消该倍率。气象球则由攻击方道具决定是否在晴雨下变属性和翻倍威力；沙暴／冰雹／雪天下仍正常变岩／冰属性并翻倍。

晴天下水蒸气的天气倍率：双方无伞为 1.5，仅攻击方持伞为 0.5，仅防守方持伞为 1.5，双方持伞为 1。雨天下按普通水属性招式规则处理。日光束／日光刃在雨天下的威力降低由防守方持伞取消；沙暴／冰雹／雪天的减伤保留。

太阳之力、干燥皮肤和雨盘的既有晴雨修正与回合末结算受持有者自身万能伞影响，叶绿素／悠游自如的加速同样受自身伞阻止；古代活性在晴天下仍能发动，队友花之礼仍能提供加成。绯红脉动只在特性持有者自身携伞时失去晴天攻击提升，目标携伞不会取消该提升。

当前不模拟日光束充能回合、打雷／暴风的动态天气命中及晨光等招式的动态天气回复；招式 `accuracy` 为基础命中回显。大日照／大雨与 Mega Sol 以引擎已有规则为边界，不将普通晴雨表直接扩展为全部极端天气机制。

## 有效特性、连续树果与实际速度

化学变化气体只压制可压制特性，特性护具保护持有者；人马一体等不可压制特性保留。破格／兆级电压／涡轮火焰只忽略可破格的防守特性，护具可保护甲壳等特性；暗影之盾不能被破格。波导防护按有效接触减伤，远隔／拳击手套消除接触后不触发。队友守护的场地开关按无盾的外部来源处理，目标护具不能代替队友来源的护具；当前接口没有该来源道具字段。

无关天气／气闸阻止天气影响，不删除实际天气。`field_info` 仅在有差异时补充有效天气和压制状态。Mega Sol 只改变使用招式时的天气，不覆盖沙暴增防、天气特性和回合末环境。

紧张感／人马一体阻止抗性果和回复果触发，气体和护具使用同一有效特性规则。普通亲子爱有独立的逐击乱数表，子击倍率在基础伤害加 2 后应用；回复果按先判倒下、再回复的顺序处理，一颗果仅消费一次。仅有合计伤害、HP 依赖／满血减伤、原生复杂多段或混合回合末效果等未建模组合会明确提示限制。

陀螺球／电球和分析读取实际速度：天气加速、冲浪之尾、古代活性／夸克充能的最高项、轻装、慢启动、飞毛腿、讲究围巾、减速道具和麻痹。最高项选择计入能力等级，临时速度修正不写回配置；固定点合并修正后统一取整，麻痹最后结算。此速度计算不模拟完整行动顺序或对手招式。陀螺球公式含末尾 +1，零速特例与电球阈值按 [Showdown 招式实现](https://github.com/smogon/pokemon-showdown/blob/master/data/moves.ts)；速度取整参照 [状态计算](https://github.com/smogon/pokemon-showdown/blob/master/sim/pokemon.ts) 和 [事件修正](https://github.com/smogon/pokemon-showdown/blob/master/sim/battle.ts)。

## 数据来源与版本策略

采用双层数据架构：

| 层级 | 来源 | 覆盖范围 | 优先级 |
|------|------|----------|--------|
| 第一层 | 《宝可梦冠军》(Pokémon Champions) Champions 规则数据（champout v1.2.0，2026-09-11） | 231 物种 / 347 种形态 | **高** |
| 第二层 | Gen9（朱紫）正作数据 | 全国图鉴 1~1025 | 低 |

当 Champions 数据与 Gen9 正作数据存在差异时，以 Champions 为准。查询结果中的 `"_data_source"` 字段标识具体来源（`"champions"` 或 `"gen9"`）。

Champions 数据按**引入规则累积保留**（M-A 275 / M-B 38 / M-C 34 种形态），每个形态带规则标签，规则顺序与当前规则由 `data/regulation_manifest.json` 统一声明。默认视图为最新规则的完整并集（不做过签过滤）；`calc` 不进行规则合法性判定。

数据中覆盖全国图鉴 1~1025 号，**包含所有形态**（含 Mega、原始回归等），不区分世代过签状态。伤害计算时不过签过滤。

### 环境情报数据层（usage / teams）

`usage` / `teams` 命令的数据独立于上述百科数据层：

| 项目 | 说明 |
|------|------|
| 来源 | pokecamp.cc（聚合 Limitless 公开赛事统计） |
| 规则 | 数据源可能使用不同 Champions 规则；以文件或返回值的 `meta.format` / `meta.regulation` 为准 |
| 样本 | 公开赛事队伍；样本量及时间窗口以各快照和返回值中的 `meta.tournament_count` / `meta.team_count` / `meta.date_range` 为准 |
| 更新 | 内置快照随版本发布；`--online` 按需请求上游并使用相应缓存，来源与日期由返回值标记 |
| 性质 | 赛事环境统计，非官方游戏内天梯数据，也非模拟器数据 |

两条命令的数据形态与分工：

| 命令 | 内置数据 | 能回答的问题 |
|------|---------|-------------|
| `usage` | `data/usage_stats.json`：312 项 M-C 赛事快照统计，窗口为 2026-10-16 至 2026-11-16（排名、胜率、Top 招式/特性/道具/性格、**SP 能力点数分配推荐**、队友） | "谁最热门"、"X 怎么加点/带什么" |
| `teams` | `data/teams_full.json.gz`：当前捆绑快照含 6,469 支队伍，来自 135 场赛事元数据，其中 134 场包含队伍数据；这 134 场详情齐全，缺失详情数为 0。每队含道具/特性/性格/招式明细。首次全量查询自动派生本地 SQLite 索引（`data/cache/teams_index.db`，可删可重建）；`data/meta_teams.json` 为前 12 支的轻量兜底 | "哪些队伍用了 X"、"某选手的队伍"、"前八队伍里谁最热门"（子集统计）、"X 最常和谁组队" |

注意：队伍数据**不含 SP/努力值分配**（teams.json 本身没有），加点类问题一律走 `usage <宝可梦名>`；两边的出现率同口径同数据集（已数值验证吻合），`teams --stats` 的价值在于子集聚合（`--placing-max` / `--tournament`）。所有 teams 查询输出硬上限 50 条，原始数据与索引不进入上下文。

`meta --online` 的 tournament usage 排名刷新失败时，先回退完整蒸馏后的在线缓存，再回退内置 usage 快照；原始 endpoint 缓存不能单独代表一份完整的在线排名结果。单只宝可梦详情可能独立请求或命中详情缓存，返回的 `meta.detail_origin`、`detail_fetched_at`、`detail_date_range`、`detail_format`、`detail_online_error` 描述该详情来源；总体排名使用 `meta.origin`、`date_range`、`format`。两组来源/日期可能不同，回答时按所引用内容分别说明。

天梯数据按来源区分：`ingame` 与 `showdown` 使用各自声明的 regulation、总榜端点和详情解析路径。传入 `--source showdown --online` 时使用 Showdown 对应的在线源；Showdown 月份以返回的 `meta.month` 为准，不能用官方 `ingame` 天梯的规则或抓取日期替代。

当前打包的两个天梯快照日期不同：官方实机为 M-C、截至 2026-11-16（data version `20261116083343008`，262 条）；仅合并 `isMega=true` 且 `linkId` 明确关联到对应非 Mega 形态的 Mega 行，其他非 Mega 形态（包括雌雄与地区形态）独立保留。Showdown 为 M-C、2026-10 月报（cutoff 1760，289 条宝可梦记录；`meta.raw_count=1,649,648` 是源报告的原始样本计数）。赛事 usage/teams 则是 M-C、2026-10-16 至 2026-11-16，312 个使用率条目、135 场赛事元数据，134 场包含队伍数据且详情缺失为 0，共 6,469 支队伍。使用时以各自响应 `meta` 中的来源和日期字段为准。
